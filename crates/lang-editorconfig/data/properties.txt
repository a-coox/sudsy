# The properties `.editorconfig` files carry and the values each accepts, for the
# `unknown-property` and `invalid-property-value` rules. One line per property: `name: words`.
#
# Sources: EditorConfig specification 0.17.2 (https://spec.editorconfig.org), and Microsoft's
# .NET code-style and code-analysis docs (dotnet/docs `docs/fundamentals/code-analysis/`, main as of
# 2026-11-05: style-rules/*, code-style-rule-options.md, configuration-options.md), including the
# naming rule format (dotnet_naming_*).
#
# Names compare case-insensitively; one `*` in a name stands for any text (`dotnet_diagnostic.*.severity`).
# Words after the colon, compared case-insensitively (`unset` is always valid):
#   bool   true false          int   a non-negative number          ...   anything
#          Checked against dotnet/roslyn Visual-Studio-2026-Version-18.7 (3fdf3c3): plain options are
#          read with bool.TryParse (Workspaces/SharedUtilitiesAndExtensions/Compiler/Core/Options/
#          EditorConfigValueSerializer.cs), so only code-style options take `:severity`.
#   sev    the value may carry a `:none|silent|suggestion|warning|error` suffix (`true:suggestion`)
#   list   a comma-separated list of the plain words (`all`, `none` and `*` are plain words too)
#   other  a literal value
