# Built-in rules

`sudsy rules` lists them, `sudsy rules <id>` explains one. `cargo xtask codegen` writes one entry per rule id to `rules.json` (next to this file; the source of the documentation site and of the VS Code extension's rule pages) and the table below from the same data: languages, category, default level, fix, description, options (name, type, default, choices, description), the presets whose `lint.rules` enable it, the upstream equivalents (entries of the [parity catalog](../parity/README.md) whose status is `rule: <id>`) and one example. Add a rule in its crate and the catalog, not here.

The example is the first fixture input (alphabetical by file name) that reports the rule, from the rule's own folder under `tests/rules/` when it has one, with the reported spans and the output of the fixes (the unsafe ones when there are no safe ones). Three rules have none because their fixtures are silent (the reports need the type or project layers, tested in `crates/*/tests`): `possible-null-dereference`, `remove-unused-usings`, `unused-private-member`; they keep the `example` text of their `RuleMeta`, which `sudsy rules <id>` prints.

## C# documentation comment rules
Twenty-four rules read the `///` and `/** */` comment of a declaration (StyleCop's SA1601, SA1604-SA1608, SA1610, SA1613-SA1617, SA1619, SA1621-SA1627, SA1629, SA1642, SA1643, SA1651); all are off by default and on in `csharp/stylecop`. They share `crates/lang-csharp/src/rules/doc_comments.rs`: the comment as a list of top-level XML elements (name, attributes, text, range) and the few facts about the declaration they need (kind, partial, accessibility, where to report). They run from the comment node (`doc-partial-required`, which also reports a missing comment, from partial declarations), so a file without documentation comments costs one kind lookup per node. Everything is syntax only, and follows StyleCop's defaults where it has settings (`documentExposedElements`, `documentInternalElements`, `documentInterfaces`, `excludeFromPunctuationCheck`, `documentationCulture: en-US`): private members need no documentation, `seealso` needs no period. Not read: a comment with `<include>` (the included file), and whether `<inheritdoc />` can inherit (a comment that has it is skipped by the rules StyleCop skips it for). A partial type or method is checked part by part: StyleCop accepts one documented part, which needs the other parts of the project. Fixes: `doc-text-ends-with-period`, `no-returns-on-void` and `no-doc-slashes-in-plain-comment` are safe (the last only for a comment that documents nothing); the wording rules (`property-summary-*`, `*-summary-standard-text`) change documentation text and are unsafe.
