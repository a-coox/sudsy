# `sudsy.yaml` (`core-config`)

One file at the repository root (`sudsy.yaml` or `.yml`; both in one directory is an error) controls formatting, rules and plugins for every language. The nearest one above the working directory (CLI) or the workspace folder (LSP) applies. An empty or comment-only file is the default config.

```yaml
extends: [preset:csharp/microsoft, ./base.yaml]   # presets, or files relative to this one (chain depth max 16)
include: ["src/**"]          # globs relative to this file; everything when empty
exclude: ["**/Generated/**"] # in addition to ignore files
analysis: standard           # fast | standard (default) | deep
format: { line_width: 100 }  # shared: every language
lint: { rules: { max-line-length: warn } }
plugins: { patterns: ["rules/*.yaml"], wasm: ["rules/team.wasm"] }
csharp:                      # also json:, yaml:
  format: { line_width: 120, brace_newline: all, preprocessor_symbols: [DEBUG] }
  lint:
    rules:
      no-empty-catch: error
      team/no-direct-datetime: { level: error, options: { allowed_in: ["**/SystemClock.cs"] } }
  semantics: { does_not_return: ["MyApp.Log.Fatal"], pure: ["MyApp.Money.Add"] }
overrides:
  - files: ["tests/**"]
    csharp: { lint: { rules: { async-suffix: "off" } } }   # overrides take format, lint and language sections
```

## Parsing rules
- Read by `serde-saphyr` with strict booleans (YAML 1.2 style): only `true`/`false` are booleans, so `off` is a valid unquoted rule level. Duplicate keys and unknown keys are errors with line and column.
- Shared `format:` keys: `line_width`, `indent_size`, `indent_style`, `final_newline`; a shared key a language does not declare is ignored; any other key there is an error. Unknown keys or invalid values in a language section are errors. Rule levels: `off`, `warn`, `error`; rule options are `{ level, options }`.
- Explicit file arguments bypass `include`/`exclude`. Paths print relative to the working directory with `/`.

## Resolution (highest first)
CLI flags (`--analysis`) -> matching `overrides` -> language section -> top-level shared settings -> `extends` chain -> `.editorconfig` -> provider defaults. Across tiers this order holds whichever file wrote the value; within a tier, chain files apply base first so the file closest to the user wins. Presets sit below all files. `sudsy config print [file]` shows the result and the source (file:line, `preset <name>`, `.editorconfig`, default) of every value. A comment-only edit re-resolves options (locations take part in equality).

## Presets and `extends`
`preset:<language>/<name>` is unversioned; see [formatting/presets.md](../formatting/presets.md). Why unversioned: presets are plain config, so a user who needs frozen output copies the file.

Limits (a repo's config is untrusted input): a file extended along several paths is read once (by canonical path), one chain reads at most 64 files, and a config or pattern file over 1 MiB or a plugin `.wasm` over 32 MiB is refused before it is read. `extends` and `plugins` paths may point outside the repository (a monorepo-level shared config above it is a legitimate use) and are not confined to it; the parser's and loaders' messages, which quote the file's text, are replaced by "details withheld" for a file outside the config's directory (extends) or the project root (plugins), so a repo cannot print another file's content into a CI log. A `sudsy.yaml` in any ancestor of the checkout is discovered.

## Schema
`schemas/sudsy.schema.json` is generated by `cargo xtask codegen` from providers' option declarations and rule metadata (including rule options; excluding plugin rule options). The VS Code extension registers it for `sudsy.yaml`. `--check` fails CI if stale. Options are declared once per provider (name, type, default, allowed values, description) and drive validation, schema and `sudsy rules`/docs.

## Zero-config
No file: C# uses `csharp/microsoft`; existing `.editorconfig` keys apply ([editorconfig.md](editorconfig.md)); JSON/YAML use their defaults.
