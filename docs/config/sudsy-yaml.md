# `sudsy.yaml` (`core-config`)

One file at the repository root (`sudsy.yaml` or `.yml`; both in one directory is an error) controls formatting, rules and plugins for every language. The nearest one above the working directory (CLI) or the workspace folder (LSP) applies. An empty or comment-only file is the default config.

```yaml
extends: [preset:csharp/google, ./base.yaml]   # presets, or files relative to this one (chain depth max 16)
include: ["src/**"]          # globs relative to this file; everything when empty
exclude: ["**/Generated/**"] # in addition to ignore files
analysis: standard           # fast | standard (default) | deep
format: { line_width: 100 }  # shared: every language
lint: { rules: { max-line-length: warn } }
languages: { toml: required, markdown: ignored }  # see below
plugins: { patterns: ["rules/*.yaml"], wasm: ["rules/team.wasm"] }
csharp:                      # also json:, yaml:, toml:
  format: { line_width: 120, brace_newline: all, preprocessor_symbols: [DEBUG] }
  lint:
    rules:
      no-empty-catch: error
      team/no-direct-datetime: { level: error, options: { allowed_in: ["**/SystemClock.cs"] } }
  semantics: { does_not_return: ["MyApp.Log.Fatal"], pure: ["MyApp.Money.Add"] }
overrides:
  - files: ["tests/**"]
    csharp: { lint: { rules: { async-suffix: "off" } } }   # overrides take format, lint and language sections
```

## Parsing rules
- Read by `serde-saphyr` with strict booleans (YAML 1.2 style): only `true`/`false` are booleans, so `off` is a valid unquoted rule level. Duplicate keys and unknown keys are errors with line and column.
- Shared `format:` keys: `line_width`, `indent_size`, `indent_style`, `final_newline`, `end_of_line`, `bracket_spacing`, `array_bracket_spacing`; a shared key a language does not declare is ignored; any other key there is an error. A top-level key that is not one of the keys above names a language section (each provider's grammar name: `csharp`, `json`, `yaml`); a name no provider has is an error with a suggestion. Unknown keys or invalid values in a language section are errors. Rule levels: `off`, `warn`, `error`; rule options are `{ level, options }`.
- Explicit file arguments bypass `include`/`exclude`. Paths print relative to the working directory with `/`.

## Resolution (highest first)
CLI flags (`--analysis`) -> matching `overrides` -> language section -> top-level shared settings -> `extends` chain -> `.editorconfig` -> provider defaults. Across tiers this order holds whichever file wrote the value; within a tier, chain files apply base first so the file closest to the user wins. Presets sit below all files. `sudsy config print [file]` shows the result and the source (file:line, `preset <name>`, `.editorconfig`, default) of every value. A comment-only edit re-resolves options (locations take part in equality).

## Dialects
A language whose provider names a config base (`LanguageProvider::config_base`: GitHub Actions on `yaml`) takes the base's section first and its own on top, in every tier that has one: the `format:` and `lint:` rules of the file's sections and of matching `overrides`, and `semantics:`. `config print` names the section each value came from. The base's rules are the dialect's too (`base_rules`), so the base's section configures them. A dialect is a language of its own for selection, docs and extra rules.

## `languages`
Maps a language name (a provider's grammar name; others are errors with a suggestion) to `required` or `ignored`, for languages that may not be installed ([../architecture/language-packs.md](../architecture/language-packs.md)). `sudsy languages sync` installs the `required` ones. Files of a language that is not installed are skipped; unless it is `ignored`, a warning names the install command and the exit status is 3. The file closest to the user wins across `extends`.

## Presets and `extends`
`preset:<language>/<name>` is unversioned; see [formatting/presets.md](../formatting/presets.md). Why unversioned: presets are plain config, so a user who needs frozen output copies the file.

Limits (a repo's config is untrusted input): a file extended along several paths is read once (by canonical path), one chain reads at most 64 files, and a config or pattern file over 1 MiB or a plugin `.wasm` over 32 MiB is refused before it is read. `extends` and `plugins` paths may point outside the repository (a monorepo-level shared config above it is a legitimate use) and are not confined to it; the parser's and loaders' messages, which quote the file's text, are replaced by "details withheld" for a file outside the config's directory (extends) or the project root (plugins), so a repo cannot print another file's content into a CI log. A `sudsy.yaml` in any ancestor of the checkout is discovered.

## Schema
`schemas/sudsy.schema.json` is generated by `cargo xtask codegen` from providers' option declarations and rule metadata (including rule options; excluding plugin rule options). The VS Code extension registers it for `sudsy.yaml`. `--check` fails CI if stale. Options are declared once per provider (name, type, default, allowed values, description) and drive validation, schema and `sudsy rules`/docs.

## Zero-config
No `extends`: every language uses Sudsy's defaults (C#: Microsoft's layout); existing `.editorconfig` keys apply ([editorconfig.md](editorconfig.md)).

What lints by default is each rule's own default level (`sudsy rules` and the Default column of [../rules/builtin.md](../rules/builtin.md)), not a preset. The rule is on (`warn`, or `error` where the code cannot work: an assignment to a `const`, `isNaN` comparison, a duplicate stage name) when it catches a likely bug, code that does not do what it says, invalid or broken output, a security problem, or deprecated or removed syntax. Style, naming, ordering, layout the formatter owns, opinions and anything that is mostly noise on real code (each checked against the conformance corpora, by findings per 10k lines and a sample of the findings) are off. So a repository with no config sees few findings, and each one is worth a look; a team that wants a tool's whole rule set extends its preset (`eslint-recommended`, `stylelint-standard`, `shellcheck`, `hadolint`, `html-validate-standard`, ...), which does not depend on these defaults. Per language:

| Language | On by default |
|---|---|
| JS, TS | The ESLint recommended rules that are bugs: duplicate keys, cases, class members and else-if conditions; assignments to `const`, imports, classes and functions; unreachable code; unsafe `finally` and negation; `use-isnan`, `valid-typeof`, `getter-return`, `require-yield`, `no-with`, `no-octal`, `no-debugger`, `no-self-assign`, regex and number literal mistakes, `no-misused-new`. Off: `no-undef` (no globals known), `no-unused-vars`, `no-redeclare`, `no-empty`, `no-case-declarations`, `no-cond-assign`, style and typescript-eslint opinions |
| CSS, SCSS, Less | Duplicate custom properties and keyframe selectors, shorthand overriding a longhand, `!important` in keyframes, unknown properties, `//` comments, declarations outside rules, unmatchable `:nth-*`, non-standard gradient directions. Off: patterns, notation, vendor prefixes, specificity, limits, rules that cannot read SCSS/Less syntax (`color-no-invalid-hex`, `at-rule-no-unknown`, `no-invalid-position-at-import-rule`) |
| HTML, Vue | Duplicate ids, references to missing ids, abstract roles, `<main>` twice, duplicate `<map>` names, empty `<title>`, deprecated elements and attributes, invalid attribute values, void end tags, unknown character references, doctype. Off: accessibility advice, element names (templates and components), style |
| YAML | Undefined aliases, duplicate keys, duplicate anchors, octal-looking numbers. Off: truthy words, quoting, flow style, document markers |
| JSON, TOML | Duplicate keys. Off: `unsafe-numbers` (large ids are common) |
| Markdown | Empty links, `#Heading` without a space, reversed links. Off: the markdownlint style rules |
| Shell | ShellCheck's quoting and command-misuse rules (`quote-variable`, `quote-at-expansion`, `cd-without-exit`, `test-and-or`, `iterate-ls-output`, ...). Off: `declare-and-assign-separately` and the style rules |
| Dockerfile | Invalid stages, `COPY --from` and ports, missing `-y`, `MAINTAINER`, repeated `CMD`/`ENTRYPOINT`/`HEALTHCHECK`, secrets in `ENV`, `USER root` last. Off: version pinning, tags, `ADD`, `sudo`, cache cleaning |
| PowerShell | Security and bug rules (plain-text passwords, `Invoke-Expression`, WMI cmdlets, misleading backtick, `$null` on the right). Off: aliases, verbs, `Write-Host`, globals, empty catch |
| GitHub Actions | actionlint's errors and `script-injection`. |
| GraphQL, HCL, Makefile, XML, INI, EditorConfig, gitignore | Invalid documents or deprecated syntax (`unique-*-name`, `deprecated-interpolation`, `timestamp-expanded`, `no-duplicate-include`, unknown or invalid EditorConfig properties, ignored `.gitignore` patterns). Off: naming, anonymous operations, empty sections, duplicate or redundant patterns |
| Protobuf | Nothing (buf's rules are style; `enum-first-value-zero` is a proto3 rule). `preset:protobuf/buf-standard` |
