# CLI (`crates/cli`)

| Command | What it does | Exit |
|---|---|---|
| `format [--check] [paths]` | Format files; `--check` reports without writing | 1 if `--check` finds changes |
| `lint [paths]` | Report diagnostics | 1 on any error-level diagnostic |
| `fix [--unsafe] [paths]` | Apply fixes (loop), then format | 1 if errors remain |
| `check [paths]` | `format --check` + `lint`, for CI; an unformatted file is an error diagnostic `format` at 1:1 | 1 on any error or unformatted file |
| `rules [term] [--language <lang>]` | List rules; an exact rule id explains it (options, presets that enable it, equivalent ids of other tools from the parity catalog); an exact id of another tool (`SA1005`, `truthy`) explains the rule that covers it; other text lists the rules whose id, description or equivalent ids contain it (case-insensitive). `--language` keeps the rules that apply to that language, shared ones included | 0; 2 when nothing matches |
| `config print [file]` | Resolved config with the source of each value | 0 |
| `init [--preset <name>] [--force]` | Write a starter `sudsy.yaml` | 0 |
| `init --from <tool> [--force] [--write-editorconfig]` | Write the `sudsy.yaml` equivalent of another tool's config in the working directory ([below](#init---from)) | 0 |
| `lsp` | Language server on stdio ([editor/lsp.md](../editor/lsp.md)) | |
| `debug parse <file>` | Developer: parse a `.cs` file with the worker, check round trip, print the tree | |

- Exit 2 on any command: a file could not be processed (syntax error, unreadable, bad option, worker unavailable) or the config is invalid. Failed files are left alone and the rest are processed. Results are reported in path order.
- `lint`, `fix`, `check`: `--format human|json|sarif|github` and `--analysis fast|standard|deep`.
  - JSON: `{version, summary, diagnostics}` with byte offsets, line/column ranges and fix edits. SARIF 2.1.0: results and rule table, no `fixes`. GitHub: `::error|warning file=,line=,col=,endLine=,endColumn=,title=::message`.
- Discovery (`core-workspace`): `.gitignore` honored also outside a git checkout, hidden directories included, `.git` excluded; explicit file arguments are always kept.
- `format` and `fix` write atomically: a temp file in the same directory, synced, then renamed over the original with its permissions kept. A file given as a symlink is resolved first, so the link stays and its target is rewritten (walks never follow symlinks).
- Diagnostic text and paths are untrusted: control characters (ANSI escapes, newlines) are shown as escapes in the human and github formats.
- A UTF-8 BOM is kept. If the semantic model is unavailable (worker crash, refusal), `lint`/`fix`/`check` print one stderr warning per distinct reason and run the other rules.
- `format`, `lint`, `fix` and `check` print one stderr warning per `.editorconfig` line that sets a C# formatting key Sudsy does not follow ([editorconfig.md](editorconfig.md)).
- `mimalloc` is the global allocator (25-40% faster on the format path).
- The JSON Schema is generated by `cargo xtask codegen`, not by the CLI.

## `init --from`
`--from yamllint|prettier|biome|eslint-jsonc|stylecop|csharpier` reads that tool's config in the working directory and writes `sudsy.yaml`. The report (stdout) lists the presets it extends, every `not migrated: <key> (<reason>)` and notes. An existing `sudsy.yaml`/`sudsy.yml` is replaced only with `--force`. The files are untrusted: read with the 1 MiB cap of Sudsy's own loader, and a parse error names the file (exit 2).

| Tool | Reads | Extends | Maps |
|---|---|---|---|
| `yamllint` | `.yamllint`, `.yamllint.yaml/.yml` | `yaml/yamllint` for `extends: default` or `relaxed` | rule levels and options, indentation, line length, spacing, blank lines, newline settings |
| `prettier` | `.prettierrc`, `.prettierrc.json/.yaml/.yml`, `package.json` `"prettier"` | `json/prettier-compat`, `yaml/prettier-compat` | `printWidth`, `tabWidth`, `useTabs` (JSON), `endOfLine`, `bracketSpacing`, `singleQuote` (YAML), `objectWrap` |
| `biome` | `biome.json`, `biome.jsonc` | `json/biome` | `formatter` and `json.formatter` (the latter wins), `json.parser`, the JSON lint rules, `useSortedKeys` |
| `eslint-jsonc` | `.eslintrc.json/.yaml/.yml`, `.eslintrc`, `package.json` `"eslintConfig"` (top level and `overrides` for `*.json*` files) | none | `jsonc/*` rules with their options, and the formatting rules (`indent`, `comma-dangle`, spacing). A flat `eslint.config.*` or `.eslintrc.js` is JavaScript: refused with an explanation |
| `stylecop` | `stylecop.json`, `.stylecop.json`, `dotnet_diagnostic.SA*.severity` in `.editorconfig` | `csharp/stylecop` | indentation, newline at end of file, do-while, `systemUsingDirectivesFirst`, `elementOrder`; severities of SA ids that map to a Sudsy rule |
| `csharpier` | `.csharpierrc`, `.csharpierrc.json/.yaml/.yml` | `csharp/csharpier-compat` | `printWidth`, `useTabs`, `indentSize`, `endOfLine` |

- Only differences from the extended presets are written.
- The mappings are checked against the parity catalog (`docs/parity/*.yaml`, embedded in the binary). The reason after `not migrated` is the catalog's `gap` or status. In debug builds a mapping whose catalog entry names a different option or rule panics; `tests/fixtures/init/<tool>/` run every mapping through that check and snapshot the result.
- C# tools also print the `.editorconfig` entries under `[*.cs]` that switch off checks Sudsy now does: `dotnet_diagnostic.IDE0055.severity = none` (CSharpier), plus every SA id the catalog marks covered (StyleCop), and a note to set `EnforceCodeStyleInBuild` so `dotnet build` reports the other IDE rules. `--write-editorconfig` appends them to `.editorconfig` (created if missing; once).
