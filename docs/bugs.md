# Known bugs

Open bugs only, one entry each: symptom, cause, suggested fix. The commit that fixes a bug deletes its entry.

- **`lsp` test `a_cancelled_pull_is_answered_with_request_cancelled` flakes under load** (`crates/lsp/tests/responsiveness.rs`, `#[ignore]` until fixed). Symptom: fails when other builds load the machine, passes alone (about 2,800 runs alone did not reproduce it). Cause: not found. The test assumes the server has read both `$/cancelRequest` notifications before it answers the `format` sent after them; under load that ordering may not hold. Suggested fix: confirm by logging the order the loop reads messages in, then make the test wait for an observable point (or make the loop drain pending notifications before answering a request), and remove the `#[ignore]`.
- **Rules kept off by default for false positives** (found by the zero-config noise check, [config/sudsy-yaml.md](config/sudsy-yaml.md#zero-config)). `no-redeclare` and `no-import-assign` (JS/TS) do not know TypeScript declaration merging (`namespace` + `const`, function + interface, imported type + local value). `no-undef` knows no globals. `no-invalid-position-at-import-rule`, `color-no-invalid-hex` (Less `#ns > .mixin()`), `at-rule-no-unknown`, `media-feature-name-no-unknown` and `function-calc-no-unspaced-operator` (reports `calc(a + b)` that has the spaces, in plain CSS too) read SCSS/Less syntax wrongly. `enum-first-value-zero` ignores `syntax = "proto2"`. `copy-from-unknown-stage`/`copy-from-own-stage` misread stages after an `ADD url#${VAR}` (the `#` ends the instruction in the Dockerfile grammar). `no-duplicate-keys`, `no-duplicate-class` on HTML with template tags inside a start tag (`{{ if }}`, `{% if %}`) treat the template words as attributes. Fix each, then turn the rule on if its sampled findings are bugs.
