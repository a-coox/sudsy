# C# formatting (`lang-csharp`)

Parser is Roslyn in the worker ([csharp-worker.md](../architecture/csharp-worker.md)); formatting, options, presets and rules are Rust. Defaults are the `csharp/microsoft` preset: width 120, indent 4, Allman braces, final newline. The full option list with values and defaults is in `schemas/sudsy.schema.json` (generated) and `sudsy config print`.

## Structure (`src/format`)
`mod.rs` dispatches on kind and grammar tag; nodes with no code are `seq` (children in order, separated by `Sep`). `spacing.rs` (space between two tokens: short exception table, default a space), `braces.rs` (types, namespaces, blocks, switch, enum, accessors), `lists.rs` (delimited lists, lambda hook), `chains.rs` (binary, member, conditional, assignment), `query.rs` (LINQ), `tags.rs` (tag table), `options.rs`. Tag defaults (`#block`, ...) are not used for C#; tags only find kinds.

## Layout rules
- Blank lines between members/statements are kept (max one). Added only by options: `blank_lines_between_members` (`separate`: before a member with a body, attribute or comment; `always`: between any two members and after the `using`s except between two fields or two `using`s), `blank_lines_after_block: require` (after a statement, member or switch section ending in `}`), `blank_line_before_comment: require` (before a `//` comment that starts an item). `blank_line_after_comment: remove` drops the blank line between the last `//` or `///` comment and its code (not in front of the first token of a file, not after `////`). A directive in front of an item leaves the blank line to the source. Empty body is `{ }` (`empty_braces`: `tight` `{}`, `expanded` `{` and `}` on two lines, except for lambdas, anonymous methods and initializers). Attribute lists: one per line on declarations and statements, inline on parameters/type parameters/lambdas. Expression-bodied members stay on the header line. A parameter, argument or attribute argument list that breaks puts its `)` on its own line, or after the last item with `closing_paren_line: same_line` (not when a comment stands in front of it). `where` clauses on their own indented lines. Embedded statements on their own indented line. `else if` stays on one line.
- Binary chains: one group per precedence level, operator first; no extra indent after `=`, `=>` or inside `if ( )`/`( )`. Conditional operator breaks before `?` and `:`. Query expressions break before each clause.
- Member chains: with at least `member_chain_min_calls` (3) calls that do not fit, one call per line; the first call stays on the head's line when the head is `this`, `base`, a predefined type, a capitalized name or a name no longer than the indent.
- Lambda as last argument (block bodies): `conditional_group` of "arguments before it on one line, body hanging" vs one argument per line.
- Interpolated strings are kept as written (expressions not formatted); raw and verbatim strings are single tokens.
- A trailing line comment on an operator makes the next operand start a new line; a line comment between chain links breaks the chain at every dot; hooks that print tokens themselves apply only when no delimiter/comma/argument start in the list has a comment.
- `#if` regions: only the active branch is formatted; other branches stay verbatim. Preprocessor symbols come from the `preprocessor_symbols` option.

## Option groups
Shared four plus `end_of_line` (`auto`|`lf`|`crlf`); `brace_newline` (`all`|`none`; `none` keeps `else`/`catch`/`finally` on new lines unless `clause_keyword_line: same_line`) with `brace_same_line` (a list of elements whose opening brace stays on the line of its head although `brace_newline` is `all`: `types` (also namespaces), `methods` (also constructors, operators, local functions), `properties` (also indexers and events), `accessors`, `anonymous_methods`, `anonymous_types`, `control_blocks` (also `switch` and bare blocks), `lambdas`, `object_collection_array_initializers`), `else_line`/`catch_line`/`finally_line` (`inherit`|`new_line`|`same_line`; `inherit` takes `clause_keyword_line`), `label_indent` (`no_change`|`one_less`|`flush_left`; the indentation of `goto` labels), `preserve_single_line_blocks` (a block written on one line stays on one line: bodies of members, accessors, lambdas and control-flow statements, with the brace of a control-flow body on its own line; not types, namespaces or `switch`; none when it holds a comment, `switch` or label) and `preserve_single_line_statements` (statements written on one line stay together, also `case 1: break;` and a whole one-line `if`/`while`/`for`/`foreach`/`do`/`try`/`using`/`lock` statement), both default `false`, `trailing_commas` (`preserve`|`never`|`multiline`; only where C# allows them), `member_chain_min_calls`, `preprocessor_symbols`, and the named layout options that express presets (`assignment_layout`, `base_list_layout`, `initializer_collapse`, `lambda_argument_hug`, `switch_arm_layout`, `wrapped_brace_line`, `inline_accessor_bodies`, `blank_lines_between_members`, `closing_paren_line`, `space_after_delegate`, `space_between_empty_for_clauses`, `sort_usings`, ...). Every preset difference is one of these; nothing is hidden.

## CSharpier compatibility
`csharp/csharpier-compat` (CSharpier 1.x) is plain options. Differential test against CSharpier 1.3.0 on the 7659-file corpus: 4952 files identical (65%); aspnetcore 2192/3122, roslyn 1657/2858, runtime 1103/1679. Known differences: CSharpier formats every `#if` branch, deeper layout differences (interpolated strings as arguments, chains inside lambdas, casts before `new`, parenthesized operands), trailing commas next to comments, some indentation and blank-line cases after `#region`/comments.

## Sorting usings (`sort_usings`, default false)
Sorts the `using` directives of every file and namespace with the ordering code of the `using-order` rule ([../rules/builtin.md](../rules/builtin.md)), fixed to `system_first`, `compare: culture_ignore_case`, `static_position: after` and `alias_position: after`: System usings, the other plain usings, `using static` (System first), aliases by alias name. The groups become one: blank lines between directives go, and the comments on the lines above a directive move with it (the comments above the first directive stay at the top). A list with a preprocessor directive in it is left alone; `global using` and `using unsafe` keep their place. The sort is a rewrite of the source text before formatting (`NodeFormatter::rewrite_source`, see [engine.md](engine.md#safety-check-every-file-every-run-not-switchable)); the output is checked against the sorted tree. Checked against CSharpier 1.3.0 ([../parity/csharpier.yaml](../parity/csharpier.yaml)).
