# JavaScript / TypeScript / JSX / TSX (`lang-js`)

## Parser
[oxc_parser](https://github.com/oxc-project/oxc) 0.158.0 (MIT), pinned to the exact version in the root `Cargo.toml` (`=0.158.0` for the five `oxc_*` crates in use; dependabot ignores them). oxc is pre-1.0 and changes its AST about weekly, so a bump is a deliberate change of `grammars/js.grammar` and `crates/lang-js/src/adapter.rs` only (the formatter and rules read our kinds), followed by the conformance run. One language `js` and one grammar cover `.js .mjs .cjs .jsx .ts .mts .cts .tsx`; the extension picks oxc's source type (`.js` is parsed as JSX, a module unless it uses script-only syntax; `.cjs` is a script; `.d.ts` is a declaration file; text of no extension, such as a Markdown fence, as JSX). Flow (`@flow` files) is not supported: oxc rejects the syntax, so the file reports syntax errors and is not formatted.

oxc's AST has no punctuation nodes and no trivia, so `adapter.rs` builds our tree (the same shape as `core-treesitter`'s, which does this for tree-sitter) from three inputs:
- the lexer's tokens (`TokensParserConfig`: every token with its span), grouped into the token kinds of the grammar (punctuation with fixed text, `Operator`, `Keyword` for reserved words and `true false null`, `Identifier` for everything else word-like including contextual keywords, `String`, `Number`, `BigInt`, `RegExp`, `TemplateChunk`, `PrivateName`, `JsxTextRun`);
- the AST's node spans, from one `oxc_ast_visit::Visit` walk (`enter_node`/`leave_node` over every `AstKind`): each AST node is a node of the tree, named as in oxc (`CallExpression`, `TSTypeAliasDeclaration`, `JSXElement`, ...); `Program` is the root; `ParenthesizedExpression` is kept; a node with no token (`JSXEmptyExpression`) is left out;
- the text between two tokens, which holds only whitespace and comments, split into `Whitespace`, `Newline`, `LineComment` and `BlockComment` tokens (a hashbang and `<!--` / `-->` lines are line comments) and attached by the shared trivia rule.

A node opens before the first token that starts in it and closes before the first token that starts after it, so a token belongs to the innermost node containing it, and every file prints back byte for byte. A zero-width `Eof` token ends the root and owns the comments at the end of the file. oxc recovers from syntax errors and reports a message and a span for each (code `syntax-error`); after a fatal error (`fatal_error`: the program is empty) the file is one `Unknown` token and the fatal error. The formatter refuses files with syntax errors. Not covered: incremental reparse, `oxc_semantic` (scopes; later), a nesting limit (oxc and the walk recurse).

## Formatting
Prettier's output is the reference (defaults: width 80, two spaces, double quotes, semicolons, trailing commas where a list breaks). Built so far: statement sequences with the source's blank lines (at most one), blocks, `if`/`else`, `for`, `for in/of/await`, `while`, `do while`, `switch`, `try`/`catch`/`finally`, `return`/`throw`/`break`/`continue`, labels, variable declarations (several declarators go one per line when any has a value), functions and their parameter lists (broken one per line with a trailing comma when too long; a lone object pattern hugs the parentheses), classes (heritage on one line, members with their blank lines, decorators of a class on their own line, of a member where the source has them), imports and exports (specifier lists break one per line when too long, a lone specifier never breaks), directives, and string, number, bigint and regular expression literals. A string takes the preferred quote unless its text holds more of those than of the other quote; escapes stay except quote escapes; numbers are lowercased with no `+` or leading zeros in the exponent, no trailing fraction zeros (`1.0` stays, `1.50` becomes `1.5`) and a `0` before a leading dot; regular expression flags are sorted; a directive keeps its quotes when it holds a quote.

Objects, arrays and destructuring (`format/object.rs`): an object literal stays expanded when the source has a line break after its `{`; an object pattern breaks when it holds a nested pattern (except as a parameter); a lone pattern parameter hugs the parentheses and a pattern on the left of `=` shares the group of the assignment; an array of two or more numbers is a fill; an array of two or more objects (or arrays) with several entries each breaks; holes and rest elements print as written (no comma after a rest); a blank line between properties stays (and breaks the object). Properties are laid out as assignments (`key: value`). `quote_props` is applied to the source text before formatting (`object::key_edits`: quotes that are not required go, `consistent` quotes all names of an object that has one that needs it); numeric names are left as written. `arrow_parens: avoid` removes the parentheses of a lone plain name the same way.

Expressions follow Prettier's algorithms, one module each: `call.rs` (arguments, hugging a last or first function/object argument, test calls, `require`), `chain.rs` (member chains cut into groups, one line or one group per line), `binary.rs` (flattened chains of one precedence, indentation by parent), `assign.rs` (assignment layouts: break-after-operator, never-break, fluid, break-lhs, chain, chain-tail; for assignments, declarators and class properties), `ternary.rs` (flat chains with nested indentation, JSX mode), `arrow.rs` (bodies, chains, hugged forms), `unary.rs` (unary, update, await, yield, spread, sequence, `return`/`throw`), `parens.rs`. Parentheses: the tree keeps `ParenthesizedExpression`, tagged `#transparent` so the safety check ignores it and its parentheses; `needs_parens` decides per node, a pair the source has is kept only when needed (or commented) and a node that needs one the source lacks gets it. Tokens the output adds that are not parentheses of an expression (`new Foo` to `new Foo()`, the parentheses of a lone arrow parameter) are added to the source text first (`format/rewrite.rs`), with the removal of stray semicolons. Template literals stay as written.

Every node without layout code of its own is printed as written, with its literals restyled (`format/literal.rs`). Parameters, variable declarators and class members print their children on one line (`util::inline`), so an annotation or initializer is that node's own text. Comments are owned by tokens and print with them; a comment before `else` or after `{` stays where the token order puts it (relocations come with the comment step). An empty statement stays a `;` line (the safety check compares nodes). A file with decorators before `export` (oxc leaves those tokens outside every node) is printed as written. `// prettier-ignore` keeps the next statement as written.

TypeScript (`format/ts/`): type annotations; type parameters (broken one per line with a trailing comma when too long, a lone simple or object type never breaks) and type arguments; union types (one line, or one `| member` per line with a leading bar and the members aligned; `{ .. } | null` hugs; a union inside type arguments or a tuple is not indented); intersections (object types stay on the line of their neighbour); function and constructor types and signatures (the type parameters, parameters and return type form one group; a lone parameter with an object type hugs the parentheses); conditional types (a chain in a branch breaks with the first, each branch indented) and mapped types (stay broken when the source breaks after `{`; a long key breaks inside its brackets); tuples; interfaces (heritage on the next line, indented, when too long; a lone plain name or one with type arguments stays on the line) and type literals (members separated by `;`, one per line when broken, broken when the source breaks after `{`); type aliases (the right side moves to the next line only when it cannot start on the line); enums (one member per line); `namespace`, `module`, `declare`, `declare global`; `import x = require(..)`, `export =`; `as`, `satisfies`, `!`, `<T>x`; class headers with several heritage clauses (`extends` and `implements` on lines of their own when too long, `{` on its own line then); parameter properties (several parameters, one of them `private x: T`, go one per line). Parentheses a type does not need (around a keyword, reference, literal or array type; around a union, function or conditional type where it stands alone: alias, type argument, tuple member, annotation of a variable, property or parameter) come out of the source before formatting (`rewrite_source`), as does the leading `&` of an intersection and the bar of a one-member union, because the safety check compares nodes; a union's bars are separator tokens (`Pipe`), so they come and go freely. Not done: comments inside unions, heritage lists and type parameters stay where the token order puts them; a union of two object types that fits on the next line is not placed there; decorators of parameter properties and the modifier order (`declare` before `private`); `semi: false` still ends interface members with `;`.

`semi: false` omits `;` and puts one in front of a statement that starts with `(`, `[`, a backtick, `+`, `-`, `/` or `<`, and after a class property when the next member starts with `[` or `*` (or is named `in` or `instanceof`), or when the property is a bare `static`, `get` or `set`.

JSX (`format/jsx.rs`): an element with no children prints as `<a></a>`; one with children goes on one line when it fits and has no tags, several attributes or several expressions, else the children are indented one per line. Children are text words and nodes in a `fill`: whitespace between a word and a tag, or at an end of the text, that a line break would lose becomes `{" "}` (the quote of `quote_style`) before the break; blank lines between children are kept once, a one-character word next to a self-closing tag stays on its line. The opening tag breaks to one attribute per line when too long (`>` on its own line unless `bracket_same_line`), except a lone string attribute; a blank line between attributes stays. An attribute string takes the preferred quote (`jsx_single_quote`; `&apos;` and `&quot;` stand for the other quote) and has no backslash escapes. An expression container hugs its expression when that is an object, array, function, call, template, `await` of one of those, or (in an element) a conditional or binary chain; else it breaks inside the braces. An element that is not an argument, array item, attribute, child, statement or branch is wrapped in `(` `)` when it breaks (always broken for an arrow returned from a call in a container); an `&&` chain keeps its JSX right side out of the chain's group. `{/* prettier-ignore */}` keeps the next element as written. The `{" "}` children are `JSXText` nodes in the tree (the adapter), which the generic safety check ignores; `safety.rs` compares each element's text by meaning (JSX's line trimming, whitespace runs, `{" "}` as a space). Not done: `fbt` tags, `singleAttributePerLine`, comments inside tags, `{...}` spread comments.

Safety check (debug builds, tests and the corpus profile; `safety.rs`): after the generic comparison of nodes and tokens, in which `;` and the text of literals are ignored, the literals of the input and the output are compared by value (a string by its content with quote escapes resolved, a number by its value, regular expression flags as a set).

Known gaps: `trailing_commas` es5/none is not yet applied to TypeScript lists (type parameters, enums, interfaces, ...); comments between a property and its comma are printed after the comma; 7 corpus files are not idempotent yet (a second format pass changes them; multi-comment lines, for example `comments/trailing-jsdocs.js`); the comment step owns it.

## Rules
Only the shared ones, which work through the grammar's tags (comments are `LineComment` and `BlockComment`). Suppression comments are `// sudsy-disable-next-line <rule>`; `// prettier-ignore` is an ignore marker for the formatter.

## Conformance
`bench/inputs/js` (real files from MUI, Vue and Excalidraw, one file of each of `.js .jsx .ts .tsx`) and a probe file per extension with the syntax of 2022-2025 (`using`, `accessor`, `satisfies`, import attributes, decorators, class static blocks, `#x in o`, variance annotations, template literal types, enums, `declare module`, JSX namespaces and fragments, hashbang, ...) are checked on every test run (`crates/lang-js/tests/js.rs`): they parse without errors, print back byte for byte, satisfy the trivia attachment rule, contain no `Unknown` token, and format with all the shared checks.
