# JavaScript / TypeScript / JSX / TSX (`lang-js`)

## Parser
[oxc_parser](https://github.com/oxc-project/oxc) 0.158.0 (MIT), pinned to the exact version in the root `Cargo.toml` (`=0.158.0` for the six `oxc_*` crates in use; dependabot ignores them). oxc is pre-1.0 and changes its AST about weekly, so a bump is a deliberate change of `grammars/js.grammar`, `crates/lang-js/src/adapter.rs` and the scope rules (`src/semantic.rs`, `src/rules/{scope,shadow,unused,imports}.rs`, which read oxc's AST and `Semantic`; the formatter and the other rules read our kinds), followed by the conformance run and the `eslint` and `typescript-eslint` parity runs. One language `js` and one grammar cover `.js .mjs .cjs .jsx .ts .mts .cts .tsx`; the extension picks oxc's source type (`.js` is parsed as JSX, a module unless it uses script-only syntax; `.cjs` is a script; `.d.ts` is a declaration file; text of no extension, such as a Markdown fence, as JSX). Flow (`@flow` files) is not supported: oxc rejects the syntax, so the file reports syntax errors and is not formatted.

oxc's AST has no punctuation nodes and no trivia, so `adapter.rs` builds our tree (the same shape as `core-treesitter`'s, which does this for tree-sitter) from three inputs:
- the lexer's tokens (`TokensParserConfig`: every token with its span), grouped into the token kinds of the grammar (punctuation with fixed text, `Operator`, `Keyword` for reserved words and `true false null`, `Identifier` for everything else word-like including contextual keywords, `String`, `Number`, `BigInt`, `RegExp`, `TemplateChunk`, `PrivateName`, `JsxTextRun`);
- the AST's node spans, from one `oxc_ast_visit::Visit` walk (`enter_node`/`leave_node` over every `AstKind`): each AST node is a node of the tree, named as in oxc (`CallExpression`, `TSTypeAliasDeclaration`, `JSXElement`, ...); `Program` is the root; `ParenthesizedExpression` is kept; a node with no token (`JSXEmptyExpression`) is left out;
- the text between two tokens, which holds only whitespace and comments, split into `Whitespace`, `Newline`, `LineComment` and `BlockComment` tokens (a hashbang and `<!--` / `-->` lines are line comments) and attached by the shared trivia rule.

A node opens before the first token that starts in it and closes before the first token that starts after it, so a token belongs to the innermost node containing it, and every file prints back byte for byte. A zero-width `Eof` token ends the root and owns the comments at the end of the file. oxc recovers from syntax errors and reports a message and a span for each (code `syntax-error`); after a fatal error (`fatal_error`: the program is empty) the file is one `Unknown` token and the fatal error. The formatter refuses files with syntax errors. Not covered: incremental reparse, a nesting limit (oxc and the walk recurse).

## Formatting
Prettier's output is the reference (defaults: width 80, two spaces, double quotes, semicolons, trailing commas where a list breaks). Built so far: statement sequences with the source's blank lines (at most one), blocks, `if`/`else`, `for`, `for in/of/await`, `while`, `do while`, `switch`, `try`/`catch`/`finally`, `return`/`throw`/`break`/`continue`, labels, variable declarations (several declarators go one per line when any has a value), functions and their parameter lists (broken one per line with a trailing comma when too long; a lone object pattern hugs the parentheses), classes (heritage on one line, members with their blank lines, decorators of a class on their own line, of a member where the source has them), imports and exports (specifier lists break one per line when too long, a lone specifier never breaks), directives, and string, number, bigint and regular expression literals. A string takes the preferred quote unless its text holds more of those than of the other quote; escapes stay except quote escapes; numbers are lowercased with no `+` or leading zeros in the exponent, no trailing fraction zeros (`1.0` stays, `1.50` becomes `1.5`) and a `0` before a leading dot; regular expression flags are sorted; a directive keeps its quotes when it holds a quote.

Objects, arrays and destructuring (`format/object.rs`): an object literal stays expanded when the source has a line break after its `{`; an object pattern breaks when it holds a nested pattern (except as a parameter); a lone pattern parameter hugs the parentheses and a pattern on the left of `=` shares the group of the assignment; an array of two or more numbers is a fill; an array of two or more objects (or arrays) with several entries each breaks; holes and rest elements print as written (no comma after a rest); a blank line between properties stays (and breaks the object). Properties are laid out as assignments (`key: value`). `quote_props` is applied to the source text before formatting (`object::key_edits`: quotes that are not required go, `consistent` quotes all names of an object that has one that needs it); numeric names are left as written. `arrow_parens: avoid` removes the parentheses of a lone plain name the same way.

Expressions follow Prettier's algorithms, one module each: `call.rs` (arguments, hugging a last or first function/object argument, test calls, `require`), `chain.rs` (member chains cut into groups, one line or one group per line), `binary.rs` (flattened chains of one precedence, indentation by parent), `assign.rs` (assignment layouts: break-after-operator, never-break, fluid, break-lhs, chain, chain-tail; for assignments, declarators and class properties), `ternary.rs` (flat chains with nested indentation, JSX mode), `arrow.rs` (bodies, chains, hugged forms), `unary.rs` (unary, update, await, yield, spread, sequence, `return`/`throw`), `parens.rs`. Parentheses: the tree keeps `ParenthesizedExpression`, tagged `#transparent` so the safety check ignores it and its parentheses; `needs_parens` decides per node, a pair the source has is kept only when needed (or commented) and a node that needs one the source lacks gets it. Tokens the output adds that are not parentheses of an expression (`new Foo` to `new Foo()`, the parentheses of a lone arrow parameter) are added to the source text first (`format/rewrite.rs`), with the removal of stray semicolons. A template literal prints each `${}` expression on one line (Prettier's unlimited width); one that spans lines or whose layout forces a break stays as written.

Every node without layout code of its own is printed as written, with its literals restyled (`format/literal.rs`). Parameters, variable declarators and class members print their children on one line (`util::inline`), so an annotation or initializer is that node's own text. Comments are owned by tokens and print with them (a block comment after `(`, `[` or `,` on the same line as what follows leads that next token: grammar tag `#glue`; one in front of `)` or `]` sits tight, tag `#close`; a multi-line block comment whose lines all start with `*` is re-indented, tag `#indentable`), with these relocations (Prettier's attachment): a trailing comment goes after the largest node that ends at its token, so its line break reaches the groups around that node and not those inside it (`JsFormatter::format_node`; a flattened binary chain does the same for its left part); a comment after `{` of a block, function body, class body or module block moves inside to a line of its own; a line comment after the `}` before `else` puts `else` on the next line; a comment before the `;` of `break`, `continue` or `debugger` goes after it; a line comment after `:` of a conditional moves the branch to the next line; in a type member list, parameter list or type parameter list the comments after a comma stay after it. Comments in front of the first token of a `return` argument, also inside parentheses, put the argument in parentheses on its own lines. An empty statement stays a `;` line (the safety check compares nodes). A file with decorators before `export` (oxc leaves those tokens outside every node) is printed as written. `// prettier-ignore` (and `sudsy-ignore`) keeps the next statement, class member, object property, type member, enum member or JSX attribute as written; `{/* prettier-ignore */}` and a comment in front of the `return` argument do the same for a JSX element. The safety check also compares every comment (whitespace ignored, order not); no corpus file is refused for it. A second comment on a line that already ends in a `//` comment goes on its own line (the printer), and the comments of a comma (array holes, import and export lists, type parameters) stay after it.

TypeScript (`format/ts/`): type annotations; type parameters (broken one per line with a trailing comma when too long, a lone simple or object type never breaks) and type arguments; union types (one line, or one `| member` per line with a leading bar and the members aligned; `{ .. } | null` hugs; a union inside type arguments or a tuple is not indented); intersections (object types stay on the line of their neighbour); function and constructor types and signatures (the type parameters, parameters and return type form one group; a lone parameter with an object type hugs the parentheses); conditional types (a chain in a branch breaks with the first, each branch indented) and mapped types (stay broken when the source breaks after `{`; a long key breaks inside its brackets); tuples; interfaces (heritage on the next line, indented, when too long; a lone plain name or one with type arguments stays on the line) and type literals (members separated by `;`, one per line when broken, broken when the source breaks after `{`); type aliases (the right side moves to the next line only when it cannot start on the line); enums (one member per line); `namespace`, `module`, `declare`, `declare global`; `import x = require(..)`, `export =`; `as`, `satisfies`, `!`, `<T>x`; class headers with several heritage clauses (`extends` and `implements` on lines of their own when too long, `{` on its own line then); parameter properties (several parameters, one of them `private x: T`, go one per line). Parentheses a type does not need (around a keyword, reference, literal or array type; around a union, function or conditional type where it stands alone: alias, type argument, tuple member, annotation of a variable, property or parameter) come out of the source before formatting (`rewrite_source`), as does the leading `&` of an intersection and the bar of a one-member union, because the safety check compares nodes; a union's bars are separator tokens (`Pipe`), so they come and go freely. Not done: comments inside unions, heritage lists and type parameters stay where the token order puts them; a union of two object types that fits on the next line is not placed there; decorators of parameter properties and the modifier order (`declare` before `private`).

`semi: false` omits `;` (also between the members of interfaces and type literals that break; one that fits keeps `;` between members) and puts one in front of a statement that follows another statement in its list and starts with `(`, `[`, a backtick, `+`, `-` (not `++`, `--`), `/` or `<` (not at the start of a block, file or case, where nothing is continued, and not as the body of an `if` or loop), and after a class property when the next member starts with `[` or `*` (or is named `in` or `instanceof`), or when the property is a bare `static`, `get` or `set`.

JSX (`format/jsx.rs`): an element with no children prints as `<a></a>`; one with children goes on one line when it fits and has no tags, several attributes or several expressions, else the children are indented one per line. Children are text words and nodes in a `fill`: whitespace between a word and a tag, or at an end of the text, that a line break would lose becomes `{" "}` (the quote of `quote_style`) before the break; blank lines between children are kept once, a one-character word next to a self-closing tag stays on its line. The opening tag breaks to one attribute per line when too long (`>` on its own line unless `bracket_same_line`), except a lone string attribute; a blank line between attributes stays. An attribute string takes the preferred quote (`jsx_single_quote`; `&apos;` and `&quot;` stand for the other quote) and has no backslash escapes. An expression container hugs its expression when that is an object, array, function, call, template, `await` of one of those, or (in an element) a conditional or binary chain; else it breaks inside the braces. An element that is not an argument, array item, attribute, child, statement or branch is wrapped in `(` `)` when it breaks (always broken for an arrow returned from a call in a container); an `&&` chain keeps its JSX right side out of the chain's group. `{/* prettier-ignore */}` keeps the next element as written. The `{" "}` children are `JSXText` nodes in the tree (the adapter), which the generic safety check ignores; `safety.rs` compares each element's text by meaning (JSX's line trimming, whitespace runs, `{" "}` as a space). A comment inside the braces of a spread attribute goes on lines of its own. Not done: `fbt` tags, `singleAttributePerLine`.

Safety check (debug builds, tests and the corpus profile; `safety.rs`): after the generic comparison of nodes and tokens, in which `;` and the text of literals are ignored, the literals of the input and the output are compared by value (a string by its content with quote escapes resolved, a number by its value, regular expression flags as a set).

Known gaps: with `semi: false` Prettier also writes the protecting `;` before the first statement of a file or block when it starts with `(`, `[` or a backtick, and Sudsy does not (the `;` would be an empty statement of its own, which the safety check reads as a change; no parity run covers the option); `trailing_commas` es5/none is not yet applied to TypeScript lists (type parameters, enums, interfaces, ...); comments between a property and its comma are printed after the comma; several comments on one line and comments in unions, heritage lists and between `return` and its argument are not placed as Prettier does. 31 corpus files are not idempotent on a second format: 3 real-world files (two member chains with an object argument, which Prettier itself reformats on its own output, and a chain of commented `as` casts) and 28 of Prettier's own tests (comments after `return` or a unary operator, in arrow chains and in JSX containers, and a few more placements).

- **Embedded expression:** a host (HTML) can hand over one expression (`SourceFile::language_version` `expression`, option `embed_mode`): it is parsed as the only element of `[ ]` and printed without the brackets (`format/embed.rs`).

## Rules
ESLint's core rules, under ESLint's ids (41; the catalog is [../parity/eslint.yaml](../parity/eslint.yaml), compared with ESLint 9 by `scripts/parity.sh eslint`): `no-debugger`, `no-with`, `no-delete-var`, `no-octal`, `no-empty-pattern`, `no-sparse-arrays`, `no-case-declarations`, `no-async-promise-executor`, `no-unsafe-negation`, `no-compare-neg-zero`, `no-prototype-builtins`, `no-shadow-restricted-names` (pattern files, `crates/lang-js/rules/syntax.yaml`) and `no-dupe-keys`, `no-dupe-class-members`, `no-duplicate-case`, `no-dupe-else-if`, `no-empty`, `no-useless-catch`, `no-self-assign`, `no-cond-assign`, `use-isnan`, `valid-typeof`, `no-extra-boolean-cast`, `no-unsafe-finally`, `no-unreachable`, `getter-return`, `require-yield`, `no-useless-escape`, `no-regex-spaces`, `no-empty-character-class`, `no-irregular-whitespace`, `no-loss-of-precision` (the `check` family, `src/rules/`, one function each, named by `checks.yaml`), and the nine that read what a name binds to (below). The ones that catch code that cannot work or does not do what it says are on by default ([Zero-config](../config/sudsy-yaml.md#zero-config)); the others (style, opinion, `no-undef` which needs globals, `no-redeclare` which does not know TypeScript declaration merging, `no-unused-vars`, `no-shadow`, `no-use-before-define`, `no-empty`, `no-useless-escape`) are off. `preset:js/eslint-recommended` enables the ones ESLint's recommended config enables, at `error` (all but `no-shadow` and `no-use-before-define`). They have no options and no fixes (ESLint offers only suggestions for most), except `no-undef`'s `globals`. The duplicate rules keep their own key identity (static names of computed keys, getter/setter pairs, `static`) instead of the shared `unique-names` family. `no-unreachable`, `getter-return`, `no-unsafe-finally` and `require-yield` decide from the syntax (`flow.rs`: jumps, `if`/`else`, `try`, `switch`, endless loops), not from a flow graph. The shared rules work through the grammar's tags (comments are `LineComment` and `BlockComment`). Suppression comments are `// sudsy-disable-next-line <rule>`; `// prettier-ignore` is an ignore marker for the formatter.

typescript-eslint's rules that need no type information, under its ids without the prefix (20; the catalog is [../parity/typescript-eslint.yaml](../parity/typescript-eslint.yaml), compared with typescript-eslint 8 by `scripts/parity.sh typescript-eslint`): `no-explicit-any`, `no-non-null-assertion`, `no-empty-object-type`, `no-namespace`, `no-require-imports`, `no-this-alias`, `consistent-type-definitions` (pattern files, `crates/lang-js/rules/typescript.yaml`) and `ban-ts-comment`, `no-extra-non-null-assertion`, `no-misused-new`, `prefer-as-const`, `no-inferrable-types`, `array-type`, `triple-slash-reference`, `adjacent-overload-signatures` (the `check` family, `src/rules/ts.rs`) and `consistent-type-imports` (`src/rules/imports.rs`, scope layer). `no-unused-vars`, `no-redeclare`, `no-shadow` and `no-use-before-define` are typescript-eslint rules too: one Sudsy rule each, which reads types, `typeof` queries and declaration merging in `.ts`, `.tsx`, `.mts` and `.cts` files. All are off by default; `preset:js/typescript-eslint-recommended` enables the eleven that typescript-eslint's `recommended` enables and Sudsy has, at `error`. They run with the upstream defaults and have no options and no fixes; `array-type` knows only the `array` style, `consistent-type-definitions` only `interface` and `consistent-type-imports` only `prefer: type-imports` with separate `import type` statements. `no-require-imports` does not report a `require` the file declares itself. The type-aware rules wait for the TypeScript worker.

### Scope layer
`no-undef`, `no-unused-vars`, `no-redeclare`, `no-const-assign`, `no-class-assign`, `no-func-assign`, `no-import-assign`, `no-shadow`, `no-use-before-define`, `consistent-type-imports` and `no-require-imports` (only for a `require(` call) read `src/semantic.rs`: oxc's `Semantic` (scopes, symbols, references) on a second parse of the file, built by the first of these rules that runs on the file and kept for the others (one per thread, replaced by the next file), so a lint run with syntax rules only never builds it and a file that does not parse gets none of these diagnostics. Results are read by span, which is the same in oxc's AST and the lossless tree. The rules follow ESLint's and typescript-eslint's helpers (what counts as a read, `args: after-used`, `hoist: functions`, declaration merging), not oxc's own linter, so that the parity runs agree on positions. Files are modules, except `.cjs`, which is CommonJS: `require`, `module`, `exports` and `global` are defined and `arguments` is defined at the top. The globals of `no-undef` are ESLint's default ones (ES2026) plus the rule's `globals` option, a list of names (ESLint's `languageOptions.globals`; it has no `readonly`/`writable` distinction); `/*global*/` and `/*exported*/` comments are not read, nor is `typeof`'s `option`. JSX tags are not references for `no-undef` and `no-use-before-define`, as in ESLint, but count as a use for `no-unused-vars` (ESLint needs `react/jsx-uses-vars` for that).

## Conformance
`bench/inputs/js` (real files from MUI, Vue and Excalidraw, one file of each of `.js .jsx .ts .tsx`) and a probe file per extension with the syntax of 2022-2025 (`using`, `accessor`, `satisfies`, import attributes, decorators, class static blocks, `#x in o`, variance annotations, template literal types, enums, `declare module`, JSX namespaces and fragments, hashbang, ...) are checked on every test run (`crates/lang-js/tests/js.rs`): they parse without errors, print back byte for byte, satisfy the trivia attachment rule, contain no `Unknown` token, and format with all the shared checks.

`scripts/parity.sh format prettier-js` compares with Prettier 3.9.10 on the same corpus: 1,000 of 1,595 comparable Prettier-test files and 2,190 of 2,456 real-world files are identical (ratchets in `tests/parity/prettier-js/differences.yaml`).

Named differences from Prettier (the parity run lists them as different files): a line comment in the header of a class or interface moves into the body (Prettier keeps it in the header; the placement is stable); JSX as the object of a member access keeps its parentheses (`(<></>).x`), because oxc cannot read `<></>.x`; a comment directly before a `;` that ends an expression statement goes after it. Files with syntax oxc does not accept (pipeline operator, do expressions, bind `::`, discard binding `void`, Flow, `let` as an identifier in `for (... of ...)`) are refused with a syntax error.
