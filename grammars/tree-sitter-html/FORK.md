# Fork of tree-sitter-html

Upstream: crates.io `tree-sitter-html` 0.23.2 (tree-sitter/tree-sitter-html, MIT, [LICENSE](LICENSE)). Regenerate `src/parser.c` after editing `grammar.js` with `scripts/grammar-regen.sh html`; `src/scanner.c` is edited by hand. Upstream's `parser.c` is ABI 14; the fork is generated by the pinned CLI (ABI 15). Generating the unpatched grammar with `--abi 14` reproduces upstream's tables.

`bindings/rust` is trimmed to the language constant (no queries, node types or doctest) so the workspace's fmt and clippy pass; `tree-sitter generate` does not touch it.

Changes:
- `grammar.js` `doctype`: the text after `doctype` is an aliased `doctype_body` node, not a hidden token.
- `grammar.js` `cdata` and `src/scanner.c` (`scan_cdata`): `<![CDATA[ ... ]]>` is a `cdata` token (an external, so it can hold `]` and `>`), allowed wherever a node is.
- `grammar.js` `rcdata_element`, `src/scanner.c` (`RCDATA_START_TAG_NAME`, `scan_raw_text`): `<textarea>` and `<title>` hold one `raw_text` up to their end tag, like `<script>` and `<style>`; upstream parsed their content as markup, so `<textarea><b>x</b></textarea>` nested a `b` element. `<title/>` is no longer accepted.
